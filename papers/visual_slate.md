# Visual Slate — one interactive representation per paper

*Working document, 2026-08-27. Goal: at least one visual, preferably interactive,
for each of the sixteen papers. Status after the first build tranche: **16/16 covered.**
All apps are single-file, zero-CDN, offline-capable HTML in `docs/`, linked from
`code.html`. Every JS computation is verified by the node harness
(`node --check` + stubbed-DOM vm run); the security app additionally embeds a
routing.py-computed reference and self-checks against it on every page load.*

## Coverage map

1. **Vehicle** — `propulsion_dashboard`, `dust_dashboard`, `flyby_dashboard`,
   `energy_dashboard` (power & redundancy), `star_map_3d` (existing)
2. **Payload** — `payload_architecture_dashboard` *(new)* — three-layer mind;
   five threat levels + four network vectors → defending layer, and what the
   defense does not guarantee
3. **Bootstrapping** — `bootstrap_ladder_dashboard` *(new)* — L1–L5 ladder +
   vitamin-mass curve (c = 0.97 → 30 kg/tonne reference marker)
4. **Analytical engineering** — `engineering_dashboard`, `fuel_radiator_dashboard`
   (existing)
5. **Computational engineering** — `engineering_dashboard` (existing; live R_eff
   knife-edge matching engineering.py: 0.48/0.94/1.39/1.85)
6. **DNA mission-ledger** — `dna_ledger_dashboard` *(new)* — working SHA-256
   hash chain (edit a block, watch tamper-evidence propagate; differential-tested
   against node crypto) + passive-vault vs settlement-refresh decay regimes
7. **Governance** — `governance_ladder_dashboard` *(new)* — E0–E7 with an
   encounter classifier; E7 as disposition-overlay; non-monotone restrictiveness
8. **Amendment** — `amendment_antinomy_dashboard` *(new)* — six requirements ×
   five mechanisms; every mechanism secures process, none correctness
9. **Fermi** — `wanderer_map` (existing; colonization front across the Galaxy)
10. **Knowledge-growth** — `knowledge_growth_dashboard` (existing; K(t) under the
    two cruise profiles)
11. **Lineage-network** — `hop_dashboard` (existing; connectivity vs hop distance)
12. **Subsystem budget** — `mass_budget_dashboard`, `fuel_radiator_dashboard`
    (existing)
13. **Routing** — `dispatch_dashboard`, `hop_dashboard` (existing) +
    `security_attack_dashboard` shares its graph machinery
14. **Ethics** — `ethics_constraints_dashboard` *(new)* — tension sections ↔
    thirteen minimum constraints, with the four §17 scenarios as stress-test
    buttons; edges shown only where the paper draws them explicitly
15. **Speciation** — `speciation_drift_dashboard` *(new)* — D(t) drift clock,
    constant vs front-loaded (rev 2), punctuated Δ_stress jumps, D_critical
    line, 10⁴–10⁵ yr mesh-reconnection window; crossing-time readout
16. **Security** — `security_attack_dashboard` *(new, generated by
    `code/make_security_dashboard.py`)* — targeted removal on the real
    127-star graph: click-to-attack, greedy replay (102→89), degree attack
    (impotent: six hubs cost 1 star each), hardening six (residual ×2.1) vs
    nine (×1.0), random baseline embedded (200 trials/k from routing.py)
