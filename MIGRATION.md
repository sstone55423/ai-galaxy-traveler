# Migrating deep-time-ai.org from GitHub Pages to Cloudflare Workers

Everything in this repo is prepared but **nothing is deployed**. The steps below
are the ones only you can run, because they need your Cloudflare credentials.
Run them in order; step 5 is the point of no return.

Reference: [Migrate from Pages to Workers](https://developers.cloudflare.com/workers/static-assets/migration-guides/migrate-from-pages/),
[Static assets](https://developers.cloudflare.com/workers/static-assets/),
[Custom domains](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/).

## What is already in place

- `wrangler.jsonc` — assets-only Worker serving `docs/`. No `main`, no binding.
  The `routes` block for the custom domain is **commented out on purpose**.
- `docs/.assetsignore` — keeps the 43 MB `.m4a` (and the GitHub Pages
  `CNAME` / `.nojekyll` artifacts) out of the upload. Without it the deploy
  fails: Cloudflare's per-asset limit is 25 MiB.
- `docs/_redirects` — generated by `code/make_papers.py`. Redirects the old
  audio path to GitHub, pins `/papers/` to `/papers`, and maps repo-shaped
  paper paths to the new canonical URLs.
- `docs/papers/<slug>/` — all sixteen papers in three forms: a typeset PDF
  (`<original-filename>.pdf`, the primary download), a web page
  (`index.html`), and the Markdown source of record (`<original-filename>.md`).
  `docs/papers.html` — the index, rebuilt from the filesystem.
- PDFs total 1.5 MB across 229 pages; the largest is 147 KB, far under the
  25 MiB per-asset limit. Total upload is about 3.7 MB.

No account ID, token, or secret is stored anywhere in the repo.

## URL scheme

Canonical citable form is `/papers/<slug>/`:

- `/papers/vehicle/` — Vehicle — `interstellar_AI_probe_paper.md`
- `/papers/payload/` — Payload — `interstellar_AI_payload_paper.md`
- `/papers/bootstrapping/` — Bootstrapping — `interstellar_AI_bootstrap_paper.md`
- `/papers/engineering-analytical/` — Analytical engineering — `interstellar_AI_engineering_paper.md`
- `/papers/engineering-computational/` — Computational engineering — `interstellar_AI_computational_paper.md`
- `/papers/dna-ledger/` — DNA mission-ledger — `interstellar_AI_dna_ledger_paper.md`
- `/papers/governance/` — Governance — `interstellar_AI_governance_paper.md`
- `/papers/amendment/` — Governed amendment — `interstellar_AI_amendment_paper.md`
- `/papers/fermi/` — Fermi — `interstellar_AI_fermi_paper.md`
- `/papers/knowledge-growth/` — Knowledge growth — `interstellar_AI_knowledge_growth_paper.md`
- `/papers/network/` — Lineage network — `interstellar_AI_network_paper.md`
- `/papers/subsystem-budget/` — Subsystem budget — `interstellar_AI_subsystem_paper.md`
- `/papers/routing/` — Fleet routing — `interstellar_AI_routing_paper.md`
- `/papers/ethics/` — Ethics — `interstellar_AI_ethics_paper.md`
- `/papers/speciation/` — Speciation — `interstellar_AI_speciation_paper.md`
- `/papers/security/` — Security — `interstellar_AI_security_paper.md`

The slugs are the series' own short names (CLAUDE.md's cross-reference naming),
not the filenames: the filenames are historical — `probe` is the vehicle paper,
and `engineering` / `computational` are the two distinct engineering papers.

Each paper directory holds three artifacts, all under the same slug:

- `/papers/<slug>/` — the web page
- `/papers/<slug>/<original-filename>.pdf` — the typeset PDF, offered first
- `/papers/<slug>/<original-filename>.md` — the Markdown source of record

The index is `/papers`. The mapping lives in `SLUGS` in `code/make_papers.py`;
a new paper added to `papers/` gets picked up automatically and, if it has no
curated slug, falls back to its filename key with a printed warning.

## Steps

**1. Regenerate, then eyeball locally.**

```
python code/make_papers.py
python -m http.server 8000 --directory docs
```

Open `http://localhost:8000/papers.html` and click through a few papers. The
local server does not emulate `html_handling`, so use `.html` paths here; the
clean URLs are exercised in step 3.

**2. Authenticate.**

```
npx wrangler login
npx wrangler whoami          # confirm the account
```

**3. Preview against the real asset router.**

```
npx wrangler dev
```

Check `/papers`, `/papers/security/`, `/papers/vehicle/`, and
`/papers/interstellar_AI_probe_paper.md` (should 301 to `/papers/vehicle/`).

**4. Deploy — still on GitHub Pages, nothing user-facing changes yet.**

```
npx wrangler deploy
```

The custom-domain `routes` block is commented out, so this publishes only to
`deep-time-ai.<your-subdomain>.workers.dev`. Verify the whole site there:
home, papers index, several papers, `challenges.html`, `code.html`, the
dashboards, `star_map_3d.html`, and the audio link (it will still bounce back
to deep-time-ai.org until step 6 — expected).

If the deploy fails on asset size, `docs/.assetsignore` was not picked up;
confirm it is at `docs/.assetsignore` and wrangler is ≥ 4.34.0.

**5. Cut the domain over. This is the irreversible-feeling step.**

Cloudflare will not create a Custom Domain on a hostname that already has a
CNAME record, so:

- In the Cloudflare dashboard → **DNS** for `deep-time-ai.org`, delete the
  records pointing at GitHub Pages (the apex `A`/`AAAA` records at
  `185.199.108–111.153` and/or the `www` CNAME to `sstone55423.github.io`).
  **Screenshot them first** — you need them verbatim to roll back.
- Uncomment the `routes` block in `wrangler.jsonc`, then `npx wrangler deploy`.
  (Equivalently: dashboard → the Worker → **Settings → Domains & Routes → Add →
  Custom Domain**.) Cloudflare creates the DNS records and the certificate.

Certificate issuance can take a few minutes. Verify `https://deep-time-ai.org/`
and `https://deep-time-ai.org/papers/security/`.

**6. Retire the Pages custom domain — required, not cosmetic.**

GitHub → repo **Settings → Pages** → clear the custom domain (leave Pages
itself **enabled**, source `main` / `/docs`). Until you do this, GitHub 301s
`https://sstone55423.github.io/ai-galaxy-traveler/...` back to
deep-time-ai.org, which after step 5 no longer holds the audio file — so the
interview link stays broken until this step is done.

Also delete `docs/CNAME` **only after** the cutover is verified; while it is
present GitHub keeps reasserting the custom domain. (It is already excluded
from the Cloudflare upload, so it does no harm on the new site.)

Then confirm:

```
curl -sS -o /dev/null -w "%{http_code}\n" \
  https://sstone55423.github.io/ai-galaxy-traveler/How_Slow_AI_Probes_Survive_Deep_Time.m4a
```

should be `200`, not `301`.

**7. Smoke test.**

```
for p in / /papers /papers/vehicle/ /papers/security/ /papers/ethics/ \
         /challenges.html /code.html /star_map_3d.html /stars_100ly.csv; do
  curl -sS -o /dev/null -w "%{http_code} $p\n" "https://deep-time-ai.org$p"
done
curl -sSI https://deep-time-ai.org/How_Slow_AI_Probes_Survive_Deep_Time.m4a | head -3
```

## Rollback

The Worker and GitHub Pages can both exist; only DNS decides who serves.

1. Cloudflare dashboard → the Worker → **Settings → Domains & Routes** → remove
   the `deep-time-ai.org` and `www` custom domains. (Re-comment the `routes`
   block in `wrangler.jsonc` so the next deploy does not re-add them.)
2. Cloudflare **DNS** → recreate the GitHub Pages records you screenshotted in
   step 5: apex `A` records to `185.199.108.153`, `185.199.109.153`,
   `185.199.110.153`, `185.199.111.153`, and `www` CNAME to
   `sstone55423.github.io`. Proxy status **DNS only** (grey cloud) so GitHub can
   issue its certificate.
3. GitHub → **Settings → Pages** → set the custom domain back to
   `deep-time-ai.org` and re-check *Enforce HTTPS* once the check passes.
   Restore `docs/CNAME` containing `deep-time-ai.org` if it was deleted.

Propagation is minutes, but GitHub's certificate provisioning can take up to an
hour, during which the site serves over HTTP only.

If you only need to undo a bad *content* deploy without touching DNS:
`npx wrangler rollback` (or **Deployments → Rollback** in the dashboard).

## Regenerating the site later

`code/make_papers.py` is the only thing to run. It is stdlib-only, like the
rest of `code/`, and rewrites `docs/papers/`, `docs/papers.html`, and
`docs/_redirects` from whatever matches `papers/interstellar_AI_*_paper.md`.
Then `npx wrangler deploy`.

PDFs are built by shelling out to **pandoc** with **xelatex**. Two things to
know if you ever change that:

- The body font is set explicitly to **DejaVu Serif**, with DejaVu Sans and
  DejaVu Sans Mono alongside it. This is not cosmetic. xelatex's default
  (Latin Modern) lacks many of the 57 non-ASCII codepoints the papers use and
  **drops them silently while still exiting 0** — `pᵢ` loses its subscript,
  `ρ` vanishes, `10⁻²²` loses its exponent. DejaVu Serif covers 54 of the 57;
  the three it misses (`≪`, `≫`, `✓`) are mapped to DejaVu Sans in the
  generated preamble.
- The generator treats any `Missing character` warning from xelatex as a build
  failure and refuses to publish that PDF, so a silently corrupted file cannot
  reach the site. If a new paper introduces a glyph DejaVu Serif lacks, the
  build will say so by name; add it to `FALLBACK_GLYPHS`.

`python code/make_papers.py --no-pdf` rebuilds only the HTML. On a machine
without pandoc or xelatex the PDF step warns and skips; the HTML build is
unaffected.
